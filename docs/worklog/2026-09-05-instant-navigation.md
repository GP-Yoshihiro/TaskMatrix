# 画面遷移の体感改善

ブランチ: `perf/instant-navigation`

## 何が起きていたか

ボタンを押してから画面が動くまで待たされる。原因は 3 つで、いずれも
推測ではなく構造として確認した。

| # | 原因 | 確認方法 |
|---|---|---|
| 1 | `loading.tsx` も `Suspense` も 1 つも無い | `find` / `grep` で 0 件 |
| 2 | 1 遷移あたり認証の往復が 3 回（proxy → layout → page） | 各ファイルの `getUser()` 呼び出しを数えた |
| 3 | データ取得が直列（`Promise.all` の無いページが多数） | ページごとの `await` 数を数えた |

1 が「押しても画面が変わらない」の直接原因。App Router では読み込み境界が
無いと、サーバー側の処理がすべて終わるまで前の画面のまま止まる。

## 直したこと

### 押した瞬間に切り替わるようにした

`loading.tsx` を 12 か所に置いた。Next のドキュメントにあるとおり、
fallback は prefetch されるため遷移が即時になる。

- `app/(app)/loading.tsx` を受け皿とし、個別の画面にも設置
- 中身の多い画面は骨組みの行数を増やし、入れ替わりで画面が跳ねないようにした

### 長引いたときに言葉を出すようにした

- 3 秒: 「読み込んでいます…」
- 10 秒: 「通信が不安定なようです。…」

**最初は何も出さない。** 一瞬で終わる遷移に文字が点滅すると、かえって遅く感じる。

### 押した直後の反応を足した

サイドバーのリンクに `useLinkStatus` で印を出す。
押せたのか分からないまま待つのが、一番遅く感じる。

### 認証の往復を減らした

- `getUser()` を React の `cache` で束ね、**layout と page の 2 回を 1 回に**。
  `cache` は 1 回の描画の中でだけ使い回すため、要求をまたいで残らない
- proxy は**保護対象外のパスで認証問い合わせをしない**ようにした。
  ログイン画面・使い方・プライバシーポリシー・画像では答えを使う場面が無い

### 直列の取得を束ねた

設定画面（3 件）とタスク画面（2 件）を `Promise.all` に。
タスク画面は、行レベルセキュリティにより他人のプロジェクトなら
どちらも空で返るため、先に取得しても情報は漏れない。

## 見送ったこと

`getClaims()` を使えば認証の往復をほぼ無くせるが、
**JWT をローカル検証する方式に変わる。** 署名鍵の設定次第で挙動が変わるため、
まず安全な `cache` だけで様子を見る。

## どう確認したか

- `lib/domain/__tests__/loading-notice.test.ts` 5 件
  （最初は出さない、段階が後戻りしない、しきい値の妥当性）
- lint / typecheck / test（763 件）/ build がグリーン
- **起動して経路を確認**した
  - `/` → `/login`、`/login`・`/guide`・`/privacy` は 200
  - **`/dashboard` → `/login`**（proxy の変更後も保護は効いている）
  - サーバーログにエラーなし

## 測れていないこと

**改善幅は数値で出せていない。** ログイン後の画面は外から測れないため。
1 の効果は構造上確実だが、2・3 の効果は実際に触っての判断になる。
