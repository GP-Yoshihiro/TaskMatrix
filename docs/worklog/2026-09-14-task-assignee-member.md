# タスクの担当をメンバーに結び付ける（第 2 期）

ブランチ: `feature/task-assignee-member`
設計書: `docs/specs/2026-09-14-project-members-design.md`

## 何を

タスクの担当を、名簿のメンバーから選べるようにした。

- `tasks.assignee_member_id` を追加（`on delete set null`）
- タスク編集に「名簿から選ぶ」欄を追加。自由入力の欄も残した
- 一覧と予定の担当表示を、解決規則にそろえた

## 解決規則

**メンバーが選ばれていればその名前、無ければ自由入力の文字、どちらも無ければ「未設定」。**

メンバーを優先するのは、名簿のほうが表記が揃っており、
同じ人が別の行に分かれないため。

`lib/domain/assignee.ts` に置き、画面・予定の双方から同じ規則を使う。

## 設計の判断

### 自由入力を残した

名簿を作る前のデータがあり、外注など名簿に載せない相手もいる。
既存データはそのまま動く。

### メンバーを消してもタスクは消さない

`on delete set null` とした。担当が外れるだけで、
作業そのものが無くなるわけではない。

### 参照が切れていれば自由入力に落ちる

メンバー名が空のときは自由入力を使う。
消されたメンバーを参照していた場合に、空の見出しを作らないため。

### 名簿が読めなくてもタスク画面は出す

担当を選べないだけで、操作は続けられる。
