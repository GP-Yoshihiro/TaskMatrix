# UI ブラッシュアップ（第 1 期：骨格）

日付: 2026-09-03
ブランチ: `feature/ui-shell`
実装計画: `docs/plans/2026-09-02-ui-shell.md`

## 何をしたか

アプリの骨格を作り直した。

- **左サイドバー**（現在地のハイライト付き）
- **どの画面幅でも閉じられる**。広い画面での好みは記憶する
- **プロジェクト切替**（一覧へ戻らずに切り替えられる）
- **パンくずと見出しの共通化**（`PageHeader`）
- 本文の幅を統一

## 着手前に測った問題

| 項目 | 変更前 |
|------|--------|
| 画面幅 1440px のときの本文幅 | 900px（左寄せ） |
| **右側の余白** | **516px** |
| 現在地の表示 | 無い |
| プロジェクトの切替 | 一覧へ戻る必要があった |
| プロジェクト内の移動 | 本文中の素のリンク |
| ページごとの最大幅 | **9 種類バラバラ**（640 / 860 / 900 / 1000 / 1100 / 1400） |

## 判断したこと

### 現在地の判定を前方一致にしない

`/projects` が `/projects/xxx/tasks` でも光ってしまうと、
どこにいるのか分からなくなる。完全一致を基本とし、
プロジェクトの「概要」だけは配下のファイル画面も自分の中と見なす。

### プロジェクト内の移動をサイドバーへ集約

本文中にあった「タスク一覧へ」などのリンクをすべて削除した。
本文に埋もれていると見落とすうえ、画面ごとに並びが違っていた。

### 画面ごとの最大幅をやめる

9 種類の幅が混在しており、画面を移るたびに本文の位置が動いていた。
骨格側で 1 か所に決め、設定画面（入力が主）だけ狭いままにした。

## 実装中に見つけて直した不具合

### 1. 保存された開閉状態が表示と食い違う

開閉の保存を「状態を更新する関数の中」で行っていた。
React はこの関数を複数回呼ぶことがあり、
**閉じたのに「開いている」と保存される**状態が実際に起きた。

読み書きを画面の外の入れ物に集め、`useSyncExternalStore` で読むようにした。

### 2. 一時的な閉じが好みとして記憶されてしまう

狭い画面では移動のたびに自動でサイドバーを閉じるが、
これが**記憶に保存されていた**。その結果、広い画面に戻ったときに
**自分で閉じた覚えのないサイドバーが閉じたまま**になっていた。

「広い画面での好み（記憶する）」と
「狭い画面での一時的な開閉（記憶しない）」を分けた。
