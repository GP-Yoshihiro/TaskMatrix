# プロジェクトメンバーとセクション（第 1 期）

ブランチ: `feature/project-members`
設計書: `docs/specs/2026-09-14-project-members-design.md`
計画: `docs/plans/2026-09-14-project-members.md`

## 何を

メンバー（名簿）とセクション（所属）を登録できるようにした。

- `project_members` / `sections` / `member_sections` の 3 表を追加
- プロジェクト内に「メンバー」画面を追加し、ナビゲーションに載せた

## なぜ

ガントチャートを担当・セクションで並べ替えたいが、
担当はタスクごとの自由入力の文字列でしかなく、所属に当たる情報も無かった。
表記ゆれで同じ人が別の行に分かれるため、並べ替えの基準にできない。

## 設計の判断

### メンバーは名簿。アカウントではない

ログインするのは引き続きプロジェクトの所有者だけ。
共有の仕組みを作らずに済み、今の「自分のデータは自分にしか見えない」構造を保てる。

### 複属は多対多で持つ

`member_sections` に付けた順で記録する。**この順の先頭が「最初の所属」**になる。
ガントチャートでは既定でそこにだけ出し、他の所属は名前を押したときに見せる
（全ての見出しに出すと、工程の合計件数が見出しの合計と一致しなくなるため）。

### 名前は正規化してから比べる

前後の空白を落とし、間の空白は 1 つにまとめる。全角の空白も空白として扱う。
「田中　太郎」と「田中  太郎」を別人として登録させないため。

### 重複の判定はアプリ側でも行う

一意制約でも弾けるが、その場合は制約違反しか返らず理由が伝わらない。
改名時は自分自身を数えない（改名せずに保存して弾かれるのを防ぐ）。

### メンバーを消してもタスクは消さない

担当が外れるだけで、作業そのものが無くなるわけではない。
第 2 期で `on delete set null` として繋ぐ。画面にもその旨を明記した。
