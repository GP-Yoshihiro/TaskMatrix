# スケジュール算出が失敗する原因の特定と修正

ブランチ: `fix/schedule-title-matching`

## 原因

算出の提案は、**タスク名で元のタスクに結び付けていた**。

```ts
const task = byTitle.get(proposal.task_title)
if (!task) return   // ← 黙って捨てる
```

名前が一字一句同じでなければ、その提案は**黙って捨てられる**。

そこへ、想定日程の対応（`0018`）で次の指示を加えた。

> 想定日程が 1 日を超えるタスクは、**複数の日に分けて配置**してください。

分けて返すとき、AI は「〇〇（1日目）」のように**名前へ印を足す**ことがある。
すると全件が結び付かず、**予定が 1 件も出ないまま、理由も分からない**状態になる。

「入力と完全に一致させる」はスキーマの説明にしか書いておらず、
**指示の本文には無かった。**

## 直したこと

### 1. 照合を少しだけ緩めた

`matchTaskTitle` を追加。完全一致 → 空白をそろえて一致 →
**分割の印を落として一致**、の順に試す。

落とすのは**数字と区切りだけで出来た末尾の括弧**に限る。
「（田中担当）」のような補足まで落とすと、別のタスクと取り違える。

### 2. 捨てた件数を必ず知らせる

`unmatchedCount` を返し、画面に出す。

- 0 件になった場合: 「…（◯件の提案が、もとのタスクに結び付きませんでした）」
- 一部だけの場合: 「◯件の提案は…除きました」

**黙って捨てない。** これが「うまくいかない理由が分からない」状態の本体だった。

日時が壊れた提案も、同じく件数に数える。

### 3. 指示に明記した

> task_title は、上のタスク一覧に書かれた名前をそのまま写してください。
> 分けて配置する場合も、すべて同じ名前にしてください。
> 「（1日目）」のような印を足さないでください。名前が違うと、その予定は捨てられます。

## どう確認したか

  （分割の印を落とす／落としすぎない、空白の違い、当てはまらない場合）
- `lib/usecases/__tests__/plan-schedule.test.ts` に 5 件追加
  （**印付きでも捨てずに結び付くこと**、結び付かない件数を返すこと）
- lint / typecheck / test（1065 件）/ build がグリーン

## 確認できていないこと

**実際の算出で直ったかは未確認。** AI の呼び出しが必要なため。
**症状が別の原因である可能性も残る。** その場合は画面の文言が手掛かりになる。
