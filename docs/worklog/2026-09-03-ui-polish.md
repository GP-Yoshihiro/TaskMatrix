# UI ブラッシュアップ（第 2 期：見やすさ）

日付: 2026-09-03
ブランチ: `feature/ui-polish`

## 何をしたか

- 共通のクラスを CSS に定義し、**ホバー・フォーカス・押下・無効の状態**を持たせた
- `Button` / `Input` / `Card` をそのクラスに寄せた
- **空状態**を「次に何をすればよいか」まで伝える形にした
- 見出しの階層を共通クラスに統一した

## 着手前に測った問題

**アプリ全体でホバー効果が `a:hover` の 1 つだけ**だった。
ボタンも一覧の行も、押せることが見た目で分からない。

原因は、見た目をすべてインラインの `style` で書いていたこと。
インラインでは `:hover` や `:focus-visible` を書けない。

## 判断したこと

### 状態は CSS に持たせる

インラインの `style` では状態を書けないため、共通クラスに移した。
副次的に、描画のたびに `transition` や `cursor` を含む
オブジェクトを作り直さずに済む。

### キーボードの枠は `:focus-visible` にする

`:focus` にすると、マウスで押したときにも枠が出て邪魔になる。
キーボードで辿っている人にだけ出す。

### 色は `color-mix` でトークンから作る

ホバーの色を固定値で書くと、ライトとダークのどちらかで破綻する。
`color-mix(in srgb, var(--color-fg) 5%, var(--color-surface))` とすることで、
**ライトでは少し暗く、ダークでは少し明るく**なる。

実測: ライト `rgb(245,245,247)` → `rgb(234,234,236)`、
ダーク `rgb(28,28,30)` → `rgb(39,39,41)`。

### 空状態は次の操作まで示す

「ファイルがまだありません。」だけでは、何をすれば埋まるのか分からない。
どこから作れるかまで書いた。

#### 確認方法についての補足

実際にマウスを乗せた見た目は確認していない。
代わりに、規則の存在・要素へのクラス付与・色の計算結果で確かめた。
