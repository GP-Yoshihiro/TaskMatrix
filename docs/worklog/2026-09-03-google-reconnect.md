# Google 連携の失効を気付ける形にする

日付: 2026-09-03
ブランチ: `feature/google-reconnect`
実装計画: `docs/plans/2026-09-03-google-reconnect.md`

## 依頼と、実際にできたこと

「本番環境に向けてカレンダーの永続的連携を実装する」という依頼だった。

**永続化そのものはアプリ側では実現できない。**
7 日で切れるのは Google Cloud の公開ステータスが「テスト」だからで、
これは Google の仕様である。

| 公開ステータス | リフレッシュトークン |
|----------------|----------------------|
| テスト | **7 日で失効** |
| 本番環境 | 失効しない（取り消し・長期未使用を除く） |

そのため、**アプリ側でできる「失効に気付ける形にする」を実装した。**
永続化には別途 Google Cloud の設定変更（ユーザーの作業）が必要。

## 直した欠陥

判定がこうなっていた。

```
connected={connection !== null}   ← 行があるかを見るだけ
```

**トークンが失効しても「連携済み」と表示され続ける。**
利用者は取り込みボタンを押して初めて失敗に気付く。
予定が同期されていないことに気付かないまま過ごす恐れがあった。

## 実装した内容

- `google_connections` に `needs_reconnect` を追加
- 更新に失敗して「繋ぎ直しが必要」なら印を立てる
- 繋ぎ直せば印を消す（再連携時の保存でも消す）
- 画面では、印が立っている間は**同期の操作を出さず**、繋ぎ直しへ誘導する

## 判断したこと

### 一時的な通信の失敗では印を立てない

`invalid_grant`（繋ぎ直しが必要）のときだけ立てる。
一時的な不調で「再接続が必要」と促すと、利用者を無駄に不安にさせる。

### 値が変わるときだけ書き込む

開くたびに書き込むのは無駄な更新になる。

### 印の書き込みに失敗しても本来の処理を止めない

印は付随的な情報であり、これで同期が止まるのは本末転倒。

### 押しても失敗する操作は出さない

印が立っている間、取り込み・書き出しのボタンを消す。
押せば必ず失敗するものを残すと、利用者を無駄に困らせる。

## 確認したこと

### 自動検証

lint（0 エラー・警告 4 件は変更前と同数）/ typecheck / test **674 件** / build すべてグリーン。
変更前の 666 件から 8 件追加。

### 実機

失効を再現するため、暗号文を復号できない値に差し替えて確認した。

| # | 確認項目 | 結果 |
|---|----------|------|
| 1 | 正常時の表示 | 「連携済み」・取り込みボタンあり |
| 2 | 失効させた直後の表示 | まだ「連携済み」（**検知は使用時のため**） |
| 3 | 取り込みを押す | 「接続が切れています」と表示され、**印が立った** |
| 4 | 再読込後の表示 | **「接続が切れています」＋「連携し直す」**。取り込みボタンは消えた |
| 5 | 正しい値に戻して印を消す | 通常の表示に戻る |
| 6 | 取り込みの実行 | 「変更はありませんでした」（正常動作） |

検証で使った控えのテーブルは削除済み。トークンは暗号化されたまま復元した。

### 残る制約

**失効は「使ったとき」にしか検知できない。**
画面を開いた時点で毎回 Google に問い合わせると、
表示が遅くなり通信も無駄になるため、そうしていない。

したがって**失効後の 1 回目は、押して失敗するまで分からない**。
2 回目以降は開いた時点で分かる。

## 永続化に必要なユーザーの作業

1. https://console.cloud.google.com/auth/audience で
   公開ステータスを**本番環境**にする
   （未審査のため同意画面に警告は出るが、トークンは失効しなくなる）
2. https://console.cloud.google.com/apis/credentials で
   本番のリダイレクト URI を追加する
   `https://task-matrix-wine.vercel.app/api/google/callback`

**2 は繋ぎ直しに必須。** 未登録のままだと、失効したときに繋ぎ直せない。
