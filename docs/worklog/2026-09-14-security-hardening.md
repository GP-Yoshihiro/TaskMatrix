ブランチ: `security/hardening`

## 点検の方法

推測ではなく、実際のコードと設定・依存関係を調べた。

### 堅牢だった点（変更不要）

| 項目 | 確認結果 |
|---|---|
| 保存パス | UUID のみで組み立て。**経路の細工はできない** |
| 署名付き URL | 60 秒で失効 |

## 直したこと

### 1. 依存関係の脆弱性（高）

`pdfjs-dist` に「悪意ある PDF で任意の JavaScript が実行される」既知の脆弱性。
**利用者が PDF を上げて解析するため、経路が実在していた。**

- 影響範囲 `>=5.6.83 <6.2.108`、使用していたのは `6.1.200`
- `overrides` で `>=6.2.108` に固定（解決後 `6.3.289`）
- `npm audit fix --force` は採らなかった。`officeparser` が 6 系へ降格し、
  いま使っている Markdown 化の機能が失われるため
- **PDF の解析が壊れていないことを実際に確かめた**（文字を取り出せた）
- 結果: 脆弱性 **0 件**

### 2. 防御用のヘッダー（高）

CSP・クリックジャッキング防止・HSTS のいずれも無かった。

- CSP は**要求ごとの nonce 方式**。スクリプトは印の付いたものだけ通す
- `style-src` だけは `unsafe-inline` を許す。画面全体で `style` 属性を使っており、
  属性は nonce では許可できない。**スクリプトを止めていれば差し込みは実行されない**
- 併せて `X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy` /
  `Permissions-Policy` / 本番のみ `Strict-Transport-Security`
- **すべての応答に付ける。** 保護対象かどうかに関わらず、埋め込みは起こりうる

#### 実際に動かして見つけた取りこぼし

画面を開いて確認したところ、次の 2 つが塞がれていた。両方とも直した。

- **Service Worker**（PWA のオフライン表示）→ `worker-src 'self'`
- **開発時の自動更新**（WebSocket）→ 開発でのみ `ws:` を許可

確認の結果、**CSP 違反は 0 件**。画面の描画・入力とも正常。

### 3. /api/health の情報開示（中）

誰でも開ける状態で、環境変数の有無と**文字数**、表と列の名前が読み取れた。

- 詳細は**管理者にだけ**返す
- 認証できない場合も `{"ok":true}` だけは返す。
  「設定が壊れてログインできない」ときの切り分けに使うため

### 4. 記録の内容（低）

Google 連携の失敗で、要求先や応答の中身が記録に残っていた。種別だけに絞った。
