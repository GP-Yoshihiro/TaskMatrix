# iOS ショートカット / Webhook API

期間: 2026-09-01 〜 2026-09-02
ブランチ: `feature/api-tokens`
設計書: `docs/specs/2026-09-01-shortcuts-api-design.md`
実装計画: `docs/plans/2026-09-01-shortcuts-api.md`

## 何をしたか

iPhone のショートカットや Siri から、タスクの追加と「今日やること」の取得ができるようにした。

| メソッド | パス |
|---|---|
| `POST` | `/api/v1/tasks` |
| `GET`  | `/api/v1/tasks/today` |

## 設計の中心

ショートカットは Cookie を持てないため、画面と同じセッション認証が使えない。
API はサーバー専用キーで接続するため **RLS が効かない**。
これまで守ってくれていた安全網が外れるので、別の形で作り直した。

**リクエストから操作対象を受け取らない。**
トークンを引くと `project_id` が決まり、すべての問い合わせをその値で絞る。
本文に `projectId` を書く場所がそもそも無いため、
「他人のプロジェクト ID を指定して覗く」攻撃が原理的に成立しない。

「毎回検証を書く」という規律に頼らず、構造で防ぐことを狙った。

## 判断したこと

- **平文を保存しない。** SHA-256 のハッシュのみ。DB が読まれても、そのままでは使えない
- **認証失敗の理由を書き分けない。** すべて 401。書き分けると有効なトークンの探索を助ける
- **回数制限は固定窓。** トークン行に 2 列持たせるだけで済み、Redis を持ち込まない
- **タスクの削除・更新を作らない。** 漏れても既存データを壊せない
- **AI 抽出を API から起動させない。** 漏れると第三者が Gemini の枠を消費できてしまう
- **キーが無ければ 503。** 黙って失敗させず、設定不備だと伝える

## 実装中に見つけた不具合

### エラーコードが実態と合っていなかった

サーバー専用キーが未設定のとき `AI_NOT_CONFIGURED` を返していた。
AI とは無関係の設定不備であり、原因を追う人を誤らせる。
`SERVICE_NOT_CONFIGURED` を新設して差し替えた。

#### 11 の詳細（JST 境界）

実データに今日の予定が無かったため、
**UTC では前日、日本時間では当日**になる時刻（`2026-09-01 22:00+00` = 9/2 07:00 JST）に
予定を一時的に作って確認した。対象タスクの期限は 2026-09-11（先）なので、
期限では選ばれない。UTC で日付を切る実装ならここで落ちる。

結果は「今日やること」に含まれ、予定のあるものとして先頭に並んだ。確認後に削除済み。

### 画面

トークンの発行（全文は 1 回だけ表示）・一覧（名前・接頭辞・最終利用日時）・
失効ダイアログ（「一度失効すると元に戻せません」）を確認した。

## 検証データの後片付け

発行した 2 本のトークン、追加した 2 件のタスク、JST 検証用の予定はすべて削除済み
（トークン 0 件、予定 4 件・タスク 3 件の元の状態に戻した）。

## 運用上の必要事項

`SUPABASE_SERVICE_ROLE_KEY` の設定が必要（2026-09-02 にユーザーが設定済み）。
このキーは RLS を通らない強い権限を持つため、クライアントへ露出させない（R-14）。
