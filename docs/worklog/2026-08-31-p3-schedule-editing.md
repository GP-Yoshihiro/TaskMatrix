## 見つかった問題と対処

### Gemini の呼び出しにタイムアウトが無く、応答が返らないと画面が固まる

2 回目の算出（確定済みの予定 3 件を含む、より大きな入力）で、
**4 分以上応答が返らず「処理中…」のまま復帰できなくなった**。
サーバー側のログにも完了記録が出ず、リクエストが宙に浮いた状態だった。

利用者から見ると、何も起きないまま操作を続けられない。
再読み込みするしかなく、しかも算出が走ったかどうかも分からない。

**対処**: `withTimeout` を追加し、Gemini の呼び出しを 90 秒で打ち切るようにした。

- 実測の所要時間は 20〜31 秒なので、その 3 倍程度を上限とした
- Server Action の `maxDuration`（120 秒）より短くし、
  基盤に打ち切られる前に日本語のエラーを返せるようにした
- タイムアウトは再試行の対象に含めた。既定モデルが固まっても
  フォールバックモデルに切り替わる

第2フェーズの AI タスク抽出も同じ呼び出し方をしており同じ弱点があったため、
そちらにも適用した。

### 前回の修正（通信断でページ全体がエラー画面）との関係

前回追加した `callAction` は「通信が切れて例外が飛ぶ」場合を拾う。
今回のタイムアウトは「応答が返らないまま待ち続ける」場合を拾う。
症状は似ているが原因が異なるため、両方が必要だった。

## 学び

長時間かかる外部 API 呼び出しでは、次の 3 つを最初から用意しておくべきだった。

1. タイムアウト（応答が返らない場合）
2. 例外の捕捉（通信が切れる場合）
3. 待機状態の表示（正常だが時間がかかる場合）

3 だけを用意して 1 と 2 を後回しにしたため、実機検証で二度つまずいた。
