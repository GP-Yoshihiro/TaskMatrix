# AI 使用量と所要時間の表示

期間: 2026-08-31 〜 2026-09-01
ブランチ: `feature/usage-logging`
設計書: `docs/specs/2026-08-31-ai-usage-display-design.md`
実装計画: `docs/plans/2026-08-31-ai-usage-display.md`

## 何をしたか

AI 処理の使用トークン量・所要時間・予測時間を画面に出せるようにした。
4 つの AI 処理（タスク抽出・予定の算出・チャットの回答・検索用データの作成）を
`ai_usage_logs` に記録し、処理中は経過時間と予測、処理後は使用量を表示する。
履歴は `/settings/usage` で確認できる。

## なぜ「残りトークン量」を出さないのか

要望には含まれていたが、**Google がその値を公開していない**。実測で確認した。

| 確認先 | 結果 |
|--------|------|
| `GET /v1beta/models/gemini-3.5-flash` | `inputTokenLimit` / `outputTokenLimit` のみ。残高の項目は無い |
| `POST .../embedContent` | `embedding` のみ。使用量は返らない |

`inputTokenLimit` は 1 リクエストの上限であって残高ではない。
取れない値を出すと「あと 99 万トークン使える」と誤解される。
ユーザーへ提示し、**残量は表示せず理由を画面に明記する**方針で承認を得た（2026-08-31）。

## 判断したこと

- **予測は平均ではなく中央値**。90 秒で打ち切られた 1 件が混ざると平均は大きく歪む
- **進捗バーは 95% で止める**。完了前に満たすと「終わったのに固まっている」と誤解される
- **失敗も記録する**。失敗してもトークンは消費されるため。ただし応答が無く実数が
  分からないので 0 を入れ、推定はしない
- **記録は追記のみ**（update / delete のポリシーを作らない）。後から書き換えられると
  記録の意味が失われる
- **記録の失敗で AI の結果を失わせない**。記録処理の例外は握りつぶす
- 料金の円換算は出さない。単価は変動し、誤った金額は残量以上に誤解を招く

## 実装中に見つけた不具合

### 1. 進捗表示が出ない（`<form action={...}>` の落とし穴）

チャットの質問欄だけ進捗が表示されなかった。
`<form action={fn}>` に渡した関数は React がトランジション内で実行するため、
その中の状態更新（進捗表示の開始）が描画に反映されるのが遅れていた。
`onSubmit` に変更して解決。ボタン表示の `isPending` も、
どの処理が動いているかを見る状態に変えた
（質問中に「検索用データを作成」ボタンまで「処理中…」になっていた）。

### 2. 開発サーバーが古い状態で固まっていた

`estimates` が undefined になり `RagChat` がエラー境界に落ちた。
HMR の切断とモジュール解決の失敗が原因。`.next` を消して再起動で解消。
コードの問題ではない。

## 確認したこと

### 自動検証

lint（0 エラー・警告 4 件は変更前と同数）/ typecheck / test 442 件 / build すべてグリーン。
PWA 時点から 52 件のテストを追加。

### RLS（SQL で直接確認）

| 確認項目 | 結果 |
|----------|------|
| RLS 有効 | true |
| 定義されているポリシー | INSERT, SELECT のみ |
| **update / delete のポリシー数** | **0**（追記のみ） |
| 所有者から見える件数 | 1 |
| **別ユーザーから見える件数** | **0** |
| 別ユーザーが他人名義で捏造できるか | **拒否された（0 件）** |
| 所有者自身による書き換え・削除 | **0 行**（値は元のまま） |

### 実機（4 処理すべて）

| 処理 | 進捗表示 | 完了後の表示 |
|------|----------|--------------|
| チャットの回答 | 「処理中… 3.0秒経過 ／ 予測 約20秒（目安）」 | 入力 396 ／ 出力 21 トークン・14.3秒・gemini-3.5-flash |
| 検索用データの作成 | — | 入力 125文字・0.9秒・gemini-embedding-2（埋め込みはトークン数を返しません） |
| 予定の算出 | 「予測を超えています（29.6秒経過）」 | 入力 819 ／ 出力 492 トークン・59.0秒・**gemini-3.7-flash** |
| タスク抽出 | 「処理中… 4.0秒経過 ／ 予測 約25秒（目安）」 | 入力 304 ／ 出力 524 トークン・46.9秒・gemini-3.5-flash |

- **予測が実測へ切り替わることを確認**: 成功 3 件（13.8 / 14.0 / 14.3 秒）が溜まった時点で
  「予測 約14秒」に変わり、「目安」の表示が消えた。中央値 14.0 秒と一致する
- **予測超過の表示を確認**: バーは 100% 幅・不透明度 0.4 の不確定表示に切り替わった
- **実際に応答したモデルが記録されることを確認**: 予定の算出では
  フォールバックせず `gemini-3.7-flash` が記録された
- 1 分以上の表示（`1分36秒`）も履歴で確認

### 検証時の補足

送信確認ダイアログ（R-21）は組み込みブラウザが自動で取り消すため、
検証中だけ `window.confirm` を承認扱いに差し替えて実行した。
送信先・目的は承認済みの範囲（Gemini API / RAG・抽出・予定算出）に限る。
