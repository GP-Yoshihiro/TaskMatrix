# 変更履歴機能（第 1 期）

日付: 2026-09-02
ブランチ: `feature/history-log`
設計書: `docs/specs/2026-09-02-history-log-design.md`
実装計画: `docs/plans/2026-09-02-history-log.md`

## 何をしたか

プロジェクト内すべてのファイルの変更履歴を、1 つのページで追えるようにした。

- ファイルの追加・編集・削除を記録
- 変更箇所（行の追加・削除）だけを保存
- 新しい順・古い順の切替、無限スクロール
- 既存の 5 版を履歴へ移行
- 表示名の登録

## インタビューで確定した要件

ユーザーとのやり取りで、当初の「GitHub 履歴連携」から**一から設計し直した**。
主な決定は次のとおり。

| 論点 | 決定 |
|------|------|
| GitHub 連携 | **アプリ機能としては作らない**（開発管理にのみ使う） |
| 保存先 | 履歴専用の表。**ファイルから独立** |
| 保存内容 | **変更箇所だけ**（全文は持たない） |
| 保存期間 | 半永久。容量上限時のみ古い順に削除（第 3 期） |
| ファイル削除時 | **履歴は残す** |
| バイナリ | 本文を抽出して差分（第 2 期） |
| データベース | **1 つのまま** |

## 判断したこと

### 履歴をファイルから独立させる

`history_entries.file_id` に**外部キーを張らない**。
張ると、ファイル削除時に履歴も連鎖削除され、
「誰がいつ何を消したか」という最も見たい情報が残らない。

### 全文と差分の両方を持たない

当初、履歴に差分を記録しても `file_versions` には全文が残り続けていた。
**両方を持つと容量削減という目的が達成できない。**
保存後に過去版を捨てるようにして、設計を実際に成立させた。

順序が重要で、**履歴を記録したあとに捨てる**。逆にすると差分が取れない。

### 変更行数は打ち切らない

保存する変更行には上限（300 行）を設けたが、
**追加・削除の行数そのものは打ち切らずに数える**。
集計まで打ち切ると、変更の規模が分からなくなる。

### 変更者名の決め方

表示名 → メールアドレスの @ より前 → 記録時に焼き込んだ名前、の順で決める。
改名は過去の履歴にも反映され、退会後も「誰か分からない」状態にならない。

## 実装中に見つけた不具合

### 差分ライブラリが最終行を誤って変更扱いにする

末尾に改行が無いテキストでは、1 行足しただけで
「最終行を削除して 2 行追加」と報告されていた。変更行数が実態とずれる。
比較の前に末尾の改行を揃えて解決した。

**これは既存のファイル別履歴画面にも存在した問題**で、
そちらは今回廃止したため、この修正で解消している。

### `'use server'` のファイルは定数を export できない

`HISTORY_PAGE_SIZE` を Server Action のファイルに置いたところ、
ビルドが失敗した。ドメイン側へ移した。

## 確認したこと

### 自動検証

lint（0 エラー・警告 4 件は変更前と同数）/ typecheck / test **568 件** / build すべてグリーン。
前フェーズの 519 件から 49 件追加。

### RLS（SQL で直接確認）

| 確認項目 | 結果 |
|----------|------|
| 別ユーザーから見える件数 | **0** |
| 別ユーザーが他人のプロジェクトに記録できるか | **拒否された** |
| 書き換え（UPDATE）のポリシー数 | **0**（記録は書き換えられない） |

### 実機

| # | 確認項目 | 結果 |
|---|----------|------|
| 1 | 既存 5 版の移行 | OK（元の日時を保って登録） |
| 2 | 一覧の表示（1 行 1 項目） | OK |
| 3 | 表示名の登録 | OK。**過去の履歴にも反映された** |
| 4 | ファイル作成の記録 | OK |
| 5 | 編集の記録 | OK（+4 行） |
| 6 | **ファイル削除後も履歴が残るか** | **残った**（下記） |
| 7 | 古い順への切替 | OK |
| 8 | 無限スクロール | OK（下記） |
| 9 | 保存時の過去版の破棄 | OK（下記） |

#### 6 の詳細

検証用のファイルを作成 → 編集 → 削除したところ、
ファイル本体と版はどちらも 0 件になった一方、
履歴は `created → updated → deleted` の 3 件が残り、
削除時に失われた 4 行も記録されていた。

**これは従来の作りでは実現できなかった。**

#### 8 の詳細

件数が少なく発動しないため、読み込み単位を一時的に 3 件へ下げて確認した。
3 件ずつ継ぎ足して 8 件で終端に到達し、取りこぼしも重複も無かった。
確認後に 50 件へ戻した。

#### 9 の詳細

保存すると版は 6 に上がる一方、`file_versions` に残るのは**現在の版 1 件のみ**で、
経緯は履歴 6 件が差分として保持している。全文の重複保存が解消された。

## 既存データの扱い

- 既存 5 版を履歴へ移行（`scripts/migrate-history.ts`）
- 移行後、過去版の全文を破棄（ユーザー承認済み）。バイナリの実体は 0 件だった

移行スクリプトは**アプリ本体と同じ差分計算を使う**（二重に実装して食い違わせないため）。
`jiti` で実行する。tsconfig の型検査からは除外している。

## 廃止したもの

ファイル別の変更履歴画面（`/files/[fileId]/history`）と `VersionHistory` 部品。
同じ役割を 2 箇所に持つと、どちらを見ればよいか分からなくなるため。
ファイル画面の「変更履歴」はプロジェクトの履歴ページへのリンクに変えた。

## 第 2 期・第 3 期でやること

| 期 | 内容 |
|----|------|
| ② | 分割表示の差分（ドラッグ調整・比率記憶）・検索（ファイル名／形式／年月／日付）・バイナリの本文抽出 |
| ③ | タグ・ロック・タグ検索・容量監視と自動削除 |

**ファイル画面の履歴ボタンからファイル名で絞り込む動作は、検索を作る第 2 期で対応する。**
第 1 期では履歴ページへ移動するところまで。
