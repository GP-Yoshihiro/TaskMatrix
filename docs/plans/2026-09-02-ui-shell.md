# UI ブラッシュアップ 実装計画（第 1 期：骨格）

ブランチ: `feature/ui-shell`

**方針:** 失敗するテストを先に書き、実装で通す（R-12）。

## 背景（実測した問題）

| 項目 | 現状 |
|------|------|
| 画面幅 1440px のときの本文幅 | 900px（左寄せ） |
| **右側の余白** | **516px** |
| 現在地の表示 | 無い |
| プロジェクトの切替 | 一覧へ戻る必要がある |
| プロジェクト内の移動 | 本文中の素のリンク |

## 第 1 期の範囲

- **左サイドバー**（現在地のハイライト付き）
- **どの画面幅でも開閉できる**。状態を記憶する
- **プロジェクト切替**（サイドバー上部）
- **パンくず**と画面見出しの共通化
- 本文の**中央寄せ**と幅の統一
- 各画面の本文中にあった移動リンクを廃止

見やすさの底上げ（共通部品・CSS 化）は第 2 期、コード整理は第 3 期。

---

## Task 1: ドメイン `lib/domain/navigation.ts`

**Produces:**
- `GLOBAL_NAV` / `PROJECT_NAV`（項目の定義）
- `projectIdFromPath(pathname): string | null`
- `isActive(pathname, href): boolean`
- `buildBreadcrumbs(input): { label: string; href?: string }[]`

**テスト:**
- 経路からプロジェクト ID を取り出す（無いときは null）
- **前方一致で誤って光らせない**（`/projects` が `/projects/x/tasks` で光らない）
- 完全一致は光る
- 子の経路では親の項目が光る（`/projects/x/files/y` で「概要」）
- パンくずの組み立て（プロジェクト内・ファイル・設定）

## Task 2: 開閉状態 `lib/domain/sidebar-state.ts`

**Produces:** `SIDEBAR_STORAGE_KEY`, `readCollapsed(read)`, 既定は「開いている」

**テスト:** 記憶の読み出し、壊れた値・保存が使えない環境での既定値

## Task 3: `components/layout/sidebar.tsx`

- 上部にプロジェクト切替（現在のプロジェクト名を押すと一覧が開く）
- 全体の項目（ホーム / プロジェクト / 設定）
- プロジェクトを開いていれば、その項目（概要 / タスク / 予定 / チャット / 履歴）
- 現在地をハイライト
- 閉じているときは幅 0（広い画面でも閉じられる）

## Task 4: `components/layout/app-shell.tsx`

- ヘッダー（開閉ボタン・アプリ名・ログアウト）
- サイドバーと本文の 2 段組
- 狭い画面では覆い被さる形で開き、背景を押すと閉じる
- 本文は中央寄せ。最大幅を統一

## Task 5: `components/layout/page-header.tsx`

パンくず・見出し・その画面の操作ボタンを置く共通部品。

## Task 6: 各画面の書き換え

`app/(app)/layout.tsx` を差し替え、各ページの見出しを `PageHeader` に統一。
本文中の移動リンク（「タスク一覧へ」など）を削除。

## Task 7: 検証と worklog

lint / typecheck / test / build と実機確認、`docs/worklog/` に記録。
