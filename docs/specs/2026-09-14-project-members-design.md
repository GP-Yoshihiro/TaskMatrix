# プロジェクトメンバーとセクション 設計書

作成日: 2026-09-14

## 背景

ガントチャートを「担当ごと」「セクションごと」に並べ替えたい。
しかし現状、担当は**タスクごとの自由入力の文字列**でしかなく、
セクション（所属）に当たる情報は存在しない。

表記ゆれで同じ人が別の行に分かれるため、並べ替えの土台として使えない。

## 決めたこと（ユーザー確認済み）

| 論点 | 決定 |
|---|---|
| メンバーの正体 | **名簿**。ログインはしない。共有の仕組みは作らない |
| 既存の担当欄 | **残す**。自由入力も引き続き使える |
| 複属の表し方 | メンバーは複数のセクションに属せる |
| 複属の見せ方 | **既定は 1 か所のみ。名前を押したときに他の所属を出す** |
| 並べ替えの見せ方 | 見出しで区切る |

### 複属を既定で隠す理由

所属する全ての見出しに出すと、工程の合計件数が見出しの合計と一致しなくなる。
「どこかで二重に数えている」と誤解させるため、既定では最初の所属にのみ出し、
必要なときだけ名前を押して他の所属を確かめられるようにする。

## データ

プロジェクトごとに 3 つの表を追加する。

| 表 | 内容 |
|---|---|
| `project_members` | メンバー（名前）。プロジェクト内で名前は一意 |
| `sections` | セクションの定義。プロジェクト内で名前は一意 |
| `member_sections` | メンバーとセクションの結び付き（多対多）。複属はここで表す |

タスクに `assignee_member_id`（`project_members` への参照、null 可）を足す。

**既存の `tasks.assignee`（text）は残す。**
担当の解決は「メンバーが選ばれていればその名前、無ければ自由入力の文字」とする。
既存データを壊さず、名簿に無い人も従来どおり扱えるようにするため。

### 行レベルセキュリティ

いずれの表も、**そのプロジェクトの所有者だけ**が読み書きできる。
既存の表と同じ考え方に揃える。

## 画面

### メンバー管理（新規）

プロジェクト内に「メンバー」を追加する。

- メンバーの追加・改名・削除
- セクションの追加・改名・削除
- メンバーへのセクション付与（複数可）

削除したメンバーを担当に持つタスクは、担当が空になる（`on delete set null`）。
タスクごと消さないのは、担当が外れただけで作業が消えるわけではないため。

### タスク編集

担当をメンバーから選べるようにする。名簿に無い人は今までどおり文字で入れられる。

### ガントチャート

並べ替えを選べるようにする。

| 並べ替え | 挙動 |
|---|---|
| 開始日順（既定） | 現状のまま |
| 担当ごと | 担当名の見出しで区切る |
| セクションごと | セクションの見出しで区切る |

セクションごとでは、複属のメンバーは**最初の所属にのみ**出す。
名前を押すと、その人の所属が一覧で出る。

担当・セクションが未設定のものは「未設定」の見出しにまとめる。

## 段階

| 期 | 内容 |
|---|---|
| 第 1 期 | メンバーとセクションの表・管理画面 |
| 第 2 期 | タスクの担当をメンバーに結び付ける |
| 第 3 期 | ガントチャートの並べ替え |

各期ごとに PR を出し、確認を得てから次へ進む。

## この設計で実装しないもの

- メンバーを利用者アカウントに結び付けること（共有の仕組みは作らない）
- メンバーごとの稼働時間・工数の集計
- セクションの入れ子（階層）
