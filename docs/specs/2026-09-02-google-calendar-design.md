# Google Calendar 同期 設計書

作成日: 2026-09-02

## 目的

TaskMatrix で確定した予定を Google カレンダーへ反映し、
Google 側で日時を動かした変更を取り込めるようにする。
iPhone のカレンダーで予定をずらす、という使い方を想定する。

## 方針（2026-09-02 ユーザー承認済み）

| 決めたこと | 内容 |
|------------|------|
| 取り込む範囲 | **日時の変更だけ** |
| 書き込み先 | **専用カレンダーを新規作成** |
| 同期の起動 | 書き出しは自動、取り込みは手動ボタン |

## 権限を最小にする

専用カレンダー方式にするため、要求する権限もそれに見合ったものにする。

| スコープ | できること |
|----------|-----------|
| `https://www.googleapis.com/auth/calendar.app.created` | **このアプリが作ったカレンダーのみ**の読み書き |

`calendar`（全カレンダーの読み書き）は要求しない。
この狭いスコープなら、利用者の既存の予定はアプリから**見ることすらできない**。
同意画面にもその範囲で表示される。

※ 実装時に実機で確認する。使えない場合はユーザーへ報告し、代替を相談する。

## リフレッシュトークンの保存

Google の再接続用トークンは長期間有効で、漏れると継続的にカレンダーへアクセスされる。

連携トークン（`api_tokens`）はハッシュで済んだが、
**こちらは実際に Google へ送るため平文が必要**になる。ハッシュ化できない。

そこで **AES-256-GCM で暗号化**し、鍵は環境変数（データベースの外）に置く。
データベースのダンプが漏れても、鍵が無ければ復号できない。

- 鍵: `GOOGLE_TOKEN_ENCRYPTION_KEY`（base64 の 32 バイト）
- 初期化ベクトルは暗号化のたびに新しく作り、暗号文と一緒に保存する
- 認証タグを保存し、復号時に改竄を検出する

## テーブル

### `google_connections`（利用者ごとに 1 行）

| 列 | 意味 |
|----|------|
| `user_id` | 接続した利用者（unique） |
| `refresh_token_encrypted` | 暗号文・初期化ベクトル・認証タグ |
| `calendar_id` | このアプリが作った専用カレンダーの ID |
| `sync_token` | 差分同期の続きを示す印 |
| `connected_at` / `last_synced_at` | |

### `schedules` への追加

| 列 | 意味 |
|----|------|
| `google_event_id` | 対応する Google の予定 ID。未反映なら null |

## 書き出し（自動）

予定を確定したときに Google へ反映する。

**TaskMatrix には確定済み予定の変更・削除の操作が無い**ため、
書き出しは「まだ Google に無い予定を作る」だけでよい。
変更・削除の反映は、その操作を実装するときに合わせて作る。

**Google への反映に失敗しても、TaskMatrix 側の操作は成功させる。**
カレンダー連携の不調で予定が確定できなくなるのは本末転倒である。
失敗した分は `google_event_id` が null のまま残り、
次の書き出しで拾われる（作り直しではなく、取りこぼしの回収になる）。

## 取り込み（手動ボタン）

Google の差分同期（`syncToken`）を使い、前回以降に変わった予定だけを取得する。
全件取得を繰り返さないため。

- 日時が変わっていれば `schedules` を更新する
- `syncToken` が失効していたら（410）、全件を取り直して印を作り直す
- 結果は「Google 側の変更で N 件を更新しました」と件数で示す

## 意図的にそうする挙動

**Google 側で予定を削除しても、TaskMatrix からは消えない。**
次の書き出しで復活する。

「日時の変更だけ取り込む」という選択の帰結である。
TaskMatrix の予定は必ずタスクに紐づくため、Google 側の削除を持ち込むと
「タスクはあるのに予定だけ消えた」状態を作ってしまう。
予定を消したいときは TaskMatrix 側で消す、という一方向に統一する。

**この挙動は画面に明記する。** 黙って復活すると不可解に映るため。

## 衝突したとき

両側が変わっていた場合、**取り込み時は Google を優先**する。
取り込みはボタンを押す明示的な操作であり、
「取り込む」と言われたものを採るのが素直である。

## 接続が切れたとき

リフレッシュトークンが失効したら（`invalid_grant`）、
接続を切れた状態にし、画面に「再接続が必要です」と表示する。
黙って同期されない状態を放置しない。

## 画面

スケジュール画面に「Google カレンダー連携」を追加する。

- 未接続: 「Google カレンダーと連携」ボタン → 同意画面へ
- 接続済み: 接続先の表示、「Google の変更を取り込む」ボタン、「連携を解除」
- 上記「意図的にそうする挙動」の説明を常時表示する

## 実装しないもの

- Google で新規作成した予定の取り込み（紐づけるタスクが無いため）
- 参加者・通知・繰り返し予定
- Google からの自動通知（公開 URL が必要。デプロイ後の課題とする）
- 複数カレンダーへの振り分け

## 運用上の必要事項

| 変数 | 用途 |
|------|------|
| `GOOGLE_CLIENT_ID` | OAuth クライアント ID |
| `GOOGLE_CLIENT_SECRET` | OAuth クライアントシークレット |
| `GOOGLE_TOKEN_ENCRYPTION_KEY` | リフレッシュトークンの暗号化鍵 |

リダイレクト URI は `http://localhost:3000/api/google/callback`。
デプロイ時は本番の URL を Google Cloud 側へ追加する必要がある。

いずれもサーバー専用であり、`NEXT_PUBLIC_` を付けない（R-14）。
