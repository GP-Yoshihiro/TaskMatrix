# AI 使用量と所要時間の表示 設計書

作成日: 2026-08-31

## 目的

AI 処理がどれだけトークンを消費し、どれだけ時間がかかるのかを利用者が把握できるようにする。
待っている間は「あとどれくらいか」を示し、終わった後は「何をどれだけ使ったか」を残す。

## 「残りトークン量」を表示しない理由

当初の要望には「残りトークン量」が含まれていたが、**Google はこれを公開していない**。
2026-08-31 に実機で確認した結果を記す。

| 確認先 | 結果 |
|--------|------|
| `GET /v1beta/models/gemini-3.5-flash` | `inputTokenLimit` / `outputTokenLimit` のみ。残量・残高の項目は無い |
| `POST .../embedContent` | `embedding` のみ。使用量は返らない |

`inputTokenLimit` は「1 回のリクエストに詰め込める上限」であり、使うほど減る残高ではない。
Gemini の無料枠は「1 分あたり・1 日あたりの回数」で管理されており、
そもそもトークンの残高という概念が存在しない。

取得できない値を画面に出すと、利用者は「あと 99 万トークン使える」と誤解する。
**残量は表示せず、画面にその理由を明記する**方針とする（2026-08-31 ユーザー承認済み）。

## 表示する 3 項目

| 項目 | 出典 | 表示場所 |
|------|------|----------|
| 使用トークン量 | Gemini の応答に含まれる `usage` | 処理直後 + 履歴ページ |
| 所要時間 | 実測（Server Action の開始〜終了） | 処理直後 + 履歴ページ |
| 予測時間 | 過去の実績の中央値 | 処理中 |

## データ設計

### 新テーブル `ai_usage_logs`

4 つの AI 処理（タスク抽出・予定作成・チャット回答・検索用データ作成）を 1 つの表に記録する。

| 列 | 型 | 意味 |
|----|----|------|
| `user_id` | uuid | 実行者。RLS の基準 |
| `project_id` | uuid (null 可) | プロジェクト削除時は null にして記録を残す |
| `operation` | text | `extract_tasks` / `plan_schedule` / `answer_question` / `build_index` |
| `model` | text | **実際に応答したモデル**（フォールバック後の値） |
| `input_tokens` / `output_tokens` | integer | 使用量 |
| `input_chars` | integer | 送った文字数。**埋め込みはトークン数を返さない**ため、その代替指標 |
| `duration_ms` | integer | 所要時間 |
| `status` | text | `succeeded` / `failed` |
| `error_code` | text | 失敗時のエラー種別 |

**失敗も記録する。** 失敗してもトークンは消費されるため、記録しないと使用量が実態より少なく見える。
ただし失敗時は応答が無くトークン数が分からないため 0 を入れる。この点は履歴ページに明記する。

**追記のみ。** 更新・削除のポリシーを作らない。使用量の記録を後から書き換えられると
記録の意味が失われるため。

### RLS

自分の行のみ select / insert 可。update / delete のポリシーは作らない。

## 予測時間の求め方

**同じ機能の直近 10 件の成功実績の中央値**を使う。

平均ではなく中央値を選ぶ理由: 90 秒でタイムアウトした 1 件が混ざると平均は大きく歪む。
中央値ならその 1 件に引きずられない。

実績が 3 件未満の間は実測にもとづく初期値を使い、画面に「目安」と明示する。

| 機能 | 初期値 |
|------|--------|
| タスク抽出 | 25 秒 |
| 予定の算出 | 20 秒 |
| チャットの回答 | 20 秒 |
| 検索用データの作成 | 5 秒 |

予測はページ表示時に算出し、Server Component から props で渡す。

## 画面

### 処理中

```
処理中… 12.4秒経過 ／ 予測 約20秒
[██████████████░░░░░]
```

- 0.1 秒ごとに更新
- **進捗バーは 95% で止める。** 完了前に 100% にすると「終わったのに固まっている」と誤解されるため
- 予測を超えたら「予測を超えています（32.1秒経過）」に切り替え、バーは不確定表示にする

### 処理直後

```
入力 3,200 ／ 出力 850 トークン・18.2秒・gemini-3.5-flash
```

埋め込み（検索用データの作成）のみ:

```
入力 12,400文字・4.1秒・gemini-embedding-2（埋め込みはトークン数を返しません）
```

### 履歴ページ `/settings/usage`

1. 冒頭の注記 —「Google は残りトークン量を公開していないため、残量は表示できません。
   ここに出るのは実際に使った量です。」
2. 今月の合計（入力・出力・合計トークン・実行回数）
3. 機能別の内訳 — どの機能が費用を食っているか判断できる
4. 直近 50 件の一覧（日時・機能・モデル・トークン・所要時間・成否）

## 実装しないもの

- **料金の円換算** — 単価は変動し、こちらが持つ価格情報は古い可能性がある。
  誤った金額は残量以上に誤解を招く
- **上限に達したら止める機能** — 残量の概念が無いため基準を置けない
- 記録の削除機能（追記のみとする方針のため）

## 失敗時の扱い

**記録に失敗しても AI の結果は返す。** 記録は付随的な機能であり、
これが原因で本来の処理が失敗するのは本末転倒であるため、記録処理の例外は握りつぶす。
